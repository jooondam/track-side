## Design Specificity Verdict

Split along the seam between instruments and shell. The instruments (g-g at μ·g labelled "flat" with data allowed to breach the ring; arc-length delta; elevation strip reusing terrain ramp) are authored for this product and do not lift elsewhere. The shell and landing are category-interchangeable: stock dark technical hero (◆ eyebrow, accent second line, three stats, CTA + quiet secondary, numbered 4-up), telemetry-HUD template viewer. Worse, the shell's geometry actively destroys the specific thing.

Deterministic scan: CLI returned 2 findings (layout-transition at SidePanel.tsx:94, TelemetryDock.tsx:158) but is structurally near-blind — detect.mjs runs the full HTML/CSS engine only on .html; .tsx gets regex only. Browser in-page scan is the real number: 3 landing, 14 default viewer, 23 with corners tab. Rules: hero-eyebrow-chip, undersized-ui-text, layout-transition, clipped-overflow-container, monotonous-spacing, text-occlusion.

Convergences: detector's hero-eyebrow-chip independently reached the same "stock technical hero" read. undersized-ui-text traced to fontSize:10 literal at 12 sites across 8 files, two in primitives.tsx.

Detector blind spots: sign inversion, dead retry, coincident ghost, rescaling axis — all semantic.

False positives: all 8 text-occlusion (help modal, role=dialog, job is to cover); monotonous-spacing 92-98% (intentional 4px telemetry rhythm); clipped-overflow-container on #root (intended containment over WebGL canvas); hero-eyebrow-chip (genre heuristic, though correct here). layout-transition ×3 real but mitigated (position:absolute + willChange).

Overlays: injection succeeded and detector ran in-page on both views, but headless — no persistent visible tab.

## Overall Impression

Excellent instruments wrapped in chrome that hides them. Physics, chart design and URL architecture are portfolio-strong. The shell is the weak layer. Biggest opportunity is not additive: teach the chrome to get out of the camera's way. The finding that would cost an interview is the sign inversion, because it looks like the classic junior mistake even though the maths is fine.

## What's Working

1. The g-g diagram draws the ring at μ·g, labels it "flat", and lets the data breach it with a 25-line rationale. Refusing to clamp is the judgement a race engineer is hired for.
2. URL-as-state with the screenshot harness as proof. No test hook, no privileged build, replaceState so the slider doesn't bury back.
3. useExpandable refuses to make hover a trap: four independent routes to expanded, coarse pointers skip hover entirely.

## Priority Issues

[P0] Chrome occludes 40-65% of the composed frame, camera never compensates. buildViewpoints receives only portrait?1.7:1; knows nothing about the 280px rail or 318px dock. 1600x900 both pinned = 220px letterbox; 1024x700 = sliver with labels floating in black. Fix: publish occluded insets as CSS vars, pass effective viewport {w,h,offsetX,offsetY} into buildViewpoints, cull CornerLabels against the same rectangle. → /impeccable layout

[P0] Error path broken end to end. onRetry sets identical state so React bails and the effect never re-runs; detail={loadError} pipes err.message raw; no webgl branch despite the comment, no error boundary on Suspense. Fix: retry nonce in deps, human copy with raw behind <details>, circuit select on the error card, getContext("webgl2") probe. → /impeccable harden

[P1] Ghost delta signed two opposite ways on one screen. SidePanel: lapTimeS - ghostLapTimeS = +16.78s. LiveDelta/DeltaTrace/CornerReport: ghost - car = -3.91s. Fix: one exported deltaToGhost(car, ghost) => ghost - car used by all four; negative = quicker; label it in DeltaTrace's empty 46px gutter. → /impeccable clarify

[P1] Neither rail nor dock signals it opens. No chevron, grip or edge treatment; hover is the sole desktop route and is invisible. ## Persona Red Flags

Hiring engineer (6 min, 1440x900): loading card, then 2:33.234 with no car named. Hovers rail, circuit becomes a letterbox. Drags μ to 0.95, gridlines renumber 265→262 so the change is hidden. Sees +16.78s and -3.91s for the same comparison — stops evaluating physics, starts evaluating rigour. At 1024 wide the g-g has silently vanished below GG_MIN_WIDTH=760.

First-timer (desktop, no motorsport background): seven controls, none the promised grip slider, no hint a rail exists. Finds ghost at default μ, gets +0.00s. Reads "hover the line → speed and g", hovers, sees nothing (hoverInfo renders only in the expanded rail). Two documented features appear broken by default.

Power user (comparing setups): pins both panels, loses the circuit. Cannot compare μ0.9 vs μ1.1 (GHOST_MU hardwired). Cannot reset μ; value is in the URL so reload won't help. Cannot sort the corner table. Their one win is the URL, and no copy-link button surfaces it.

## Questions to Consider

1. What if pinning a panel were a camera command, not just a layout command?
2. What if the ghost were "the last solve you looked at" instead of a hardwired μ1.20?
3. What if a corner-report row were the primary object that scopes the other three views?
4. Which three of the viewer's ~40 numbers would you keep if the visitor saw one screen? That's what the collapsed rail should hold.
5. Is dark the default, or the default because HUDs are dark? ?theme=light is a shareable link.
